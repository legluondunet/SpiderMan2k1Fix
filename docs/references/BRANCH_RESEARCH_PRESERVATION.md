# Branch-cleanup technical preservation audit

**Audit date:** 2026-10-24. This document records what was checked **before deleting old Git branches** in `legluondunet/SpiderMan2k1Fix`. Branch comparisons are **not** equivalent to a full dynamic game test or independent machine-code reconstruction. GitHub reports many historical feature branches as **diverged**, even when their corrected end result was later merged through another PR.

> **No branches were deleted by this audit.** Keep `main`, all currently **open PR head branches**, and this documentation PR's branch until they are merged or explicitly closed. On the audit date, `docs/remove-redundant-esc-section` was the **open PR #42 head**. If its status has changed, check GitHub afresh before pruning.

## Before deleting any branch

1. **Merge or close open PRs first.** In particular PR #42 (`docs/remove-redundant-esc-section`) was open at the audit snapshot, and **this preservation PR must remain available until merged**.
2. Use GitHub's **Compare** for any last-minute branch edits: an **ahead/diverged** branch may contain an unmerged experiment, not necessarily safe code to restore. A **behind/ahead=0** branch is generally easier to remove after checking PR status.
3. Keep a branch or permanent non-branch artifact if you may later want the **exact experimental code**, especially the closed, unmerged PR #5 Wine smoke scripts, PR #19 ESC D3D7 tracer, and PR #24 F9 readback tracer. **This audit preserves their knowledge, not their executable patch implementations.**
4. Verify the [F12 archives](F12_EXIT_ARCHIVE_SUMMARY.md) and [function catalog](ORIGINAL_EXE_FUNCTION_CATALOG.md) are merged to `main` before deleting their last branch refs.
5. Never rewrite `main` or delete the original game/patch history to “clean up branches.” Removing a branch does not remove a merged change, and historical pull-request discussion may still refer to older filenames and experimental options.

## Evidence boundaries

The two large F12 journals were compared with the archived F12-related branch documents; the relevant native exit and static-code observations are retained in `main`. Many other old branches contain **alternative implementation prototypes**, whose detailed code is not recopied. This is a **technical preservation audit**, not a guarantee that all historical experiments were successful or that every binary instruction in every branch has a proven function name.

The catalog specifically marks **instruction sites vs true callable routines**, **game globals vs routines**, and **verified vs inferred** behaviors. Do not equate a label in a debug trace, a native request number or one successful process exit with a complete original-source decompilation.
