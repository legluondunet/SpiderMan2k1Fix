# SpiderMan2k1Fix — experimental unified build (NOT A RELEASE)

This test-only Spider-Man 2001 compatibility launcher uses one project DLL
(`game/fix.dll`) and does not install a local `winmm.dll`. It has passed
native Windows PE32 **synthetic** installation and rollback tests, but not yet
been approved for actual game sessions on Windows 11 or Wine/Proton.

**Never use this candidate to modify your existing working installation.**
Use a new empty folder with the test launcher and one legitimate retail ISO/CUE
(with its referenced BIN/IMG when required). No game data is bundled.

## Layout

```text
spiderman2k1fix/
  SpiderMan2k1Fix.exe         # required launcher, installer and verifier
  SpiderMan2k1Fix.ini         # generated by game on first successful launch
  SpiderMan2k1Fix.log
  SpiderMan2k1Fix_installer.log
  SpiderMan2k1Fix_inspect.log # only after --inspect
  state/
    installed-game.sha256
    installed-resources.sha256
  docs/
    README.md
    CHANGELOG.md
    LICENSE
  third_party/
    SDL3/
      SDL3.dll
      LICENSE.txt
  linux/
    spiderman-focus-helper
  game/
    SpideyPC.exe
    fix.dll
    ... original disc files and game-generated files
```

No `mods/` directory is created until actual modding support is implemented.
`state/` contains only two installer-owned SHA-256 receipts; do not edit them.
Screenshots are written beside the launcher when writable. The native X11
focus helper is stored under the launcher's `linux/` directory.

## Commands (experimental)

Use the launcher from the **root**, never `game/SpideyPC.exe` directly:

```text
SpiderMan2k1Fix.exe --version
SpiderMan2k1Fix.exe --inspect original.iso
SpiderMan2k1Fix.exe --install-only
SpiderMan2k1Fix.exe --verify
SpiderMan2k1Fix.exe
```

On Wine/Proton, use the corresponding compatibility launcher to run this
Windows x86 executable; do not copy project DLLs into system folders.

Installation checks the supported original executable's exact SHA-256
(`0a11a49f3f63d4bb15650f322d654553fc47234b01885b852a058ff074689dea`),
then installs the complete original Wise data superset and verified bundled
resources. It stages the five target directories and publishes `state/`
last; on a staging/publish failure it attempts rollback rather than adopting
unrecognized data. A previous `spiderman2001/` installation is **not**
migrated automatically; use a separate test folder.

`--verify` reads both receipts and checks every managed file without
repairing or launching. `--install-only` can upgrade only authenticated
project resources and does not touch original game data, saves or INI.
`--launch-no-verify` skips normal resource-receipt preflight but the unified
startup still **requires the supported original game EXE hash** and the
correct bundled `fix.dll`; it does not bypass the authenticity guard.

`fix.dll` is loaded through a memory-only PE import-name alias in a
suspended process. The on-disk `SpideyPC.exe` is never patched. Native
Windows/Wine WinMM remains the operating-system version.

## One-time first-launch diagnostic logging

The installer always writes `SpiderMan2k1Fix_installer.log` beside the
launcher during installation. The **first actual game launch**, when
`SpiderMan2k1Fix.ini` is still absent, automatically writes
`SpiderMan2k1Fix.log` as if **[Debug] Log=1**. The launcher records its
startup first, even before the suspended game process starts; the core
continues the same log after its verified DirectDraw bootstrap.

The generated INI contains **[Debug] Log=0** permanently, so subsequent
sessions do not produce additional runtime logs. The initial log remains
available for diagnosis and is not removed after the game closes. No extra
file is created in `state/`; its only contents remain the two SHA receipts.

An **existing user INI is never changed or overridden**: `Log=1` keeps
logging on every game session; `Log=0` keeps logging off. The first-launch
automatic override applies only if the INI is entirely absent, so placing
a user-configured INI before the first launch honors its setting. If the
first game session crashes after generating an INI, the startup log is
still available and the next launch uses the generated `Log=0`.

The *installer log* is independent of the in-game debug switch and continues
to record verification, installation, updates and launch errors.
